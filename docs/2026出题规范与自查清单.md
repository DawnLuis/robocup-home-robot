# 2026 出题规范与自查清单

本文整理《2026 中国机器人大赛服务机器人仿真项目出题指南》与《2026 年度赛事规则
（服务机器人 · 服务机器人仿真）》中对**出题**的硬性要求，并给出对应的自动化检查项。
出题与提交前按本清单逐条核对。

---

## 一、依据文件

| 文件 | 用途 |
|------|------|
| 2026 中国机器人大赛服务机器人仿真项目出题指南 | 题面格式的唯一标准（附录A 物体字段格式、附录B 指令语言格式、附录C 指令-自然语言对应、附录D XML 结构） |
| 2026 年度赛事规则（服务机器人仿真项目） | 阶段开关、评分公式、提交规范与罚则 |

## 二、提交要求

- 每个阶段、每个子项目（指令语言 / 自然语言）各提交 **30 道题**；未提交队伍无抽题资格。
- **少交一题扣该队总分 500 分**；题目出现**语法错误或格式错误**，每题扣 500 分
  （同一道题扣分上限 500）。
- 题目以**压缩包**提交；**题目文件命名格式为 `<抽签顺序>-<题目顺序>`**（如 `7-01.xml`）。
- 参赛代码压缩包**主文件夹统一命名为 `<抽签顺序>-<学校>-<队伍名称>`**（不加任何后缀），
  内含代码与题目两个压缩包。
- 提交截止后，裁判组**从每队 30 道题中随机抽取 2 道**汇总成题库并逐题审核 ——
  因此 30 道题必须**每一道**都合规。
- 审题阶段有**半小时各队自我调试时间**，用于发现题目的逻辑问题。

## 三、环境信息（env）

| # | 要求 | 检查项 |
|---|------|--------|
| 1 | 第一阶段 `mis/err/ans` 均为 `off`，第二阶段均为 `on` | `check_appendixB_2026.py`（按目录名判定阶段） |
| 2 | `info` 按物体编号顺序排列；编号自 0 起的非负整数、不断号；`robot=0`、`human=1` 且场景中有且仅有一人；位置编号非负 | `check_rules_2026.py` / `check_submit_2026.py` |
| 3 | 字段完整性：robot 含 `hold,plate,at`；小物体含 `sort,size,color,at(或 inside)`；大物体含 `sort,size,at`；容器含 `sort,size,at,type,opened(或 closed)` | `check_syntax_2026.py` / `check_submit_2026.py` |
| 4 | `sort` 必须居首，其余字段按上述顺序；`at` 在 `type` 之前 | 同上 |
| 5 | 同一行字段的物体 id 必须与 `sort` 一致 | `check_submit_2026.py` |
| 6 | 不可出现完全一样的大物体或小物体 | `check_rules_2026.py` |
| 7 | 一个位置内至多只能有一个大物体（可放多个小物体） | `check_rules_2026.py` |
| 8 | 在 `mis`、`err`、`extra` 部分出现的字段可以省略；`robot` 的 `hold`/`plate` 中的小物体可省略 `at`/`inside` | `check_submit_2026.py`（豁免逻辑） / `check_stage2_2026.py` |
| 9 | `mis` 可含：小物体 `at/inside`、大物体 `at`、robot 的 `plate`、容器 `opened/closed` | `check_stage2_2026.py` |
| 10 | `err` 的 `r` 写正确信息、`w` 写错误信息；组合限于 `at→{at,inside}`、`inside→{at,inside}`、`plate→{at,inside}`、`opened↔closed`；`w` 不得与 `info` 矛盾 | `check_stage2_2026.py` |
| 11 | `extra` 中的每条信息必须在该题 `instr` 的 `info` 中指出 | `check_stage2_2026.py` |
| 12 | 题目不得包含一开始就被破坏的约束 | `check_cons_init.py` |

**env 常见格式错误**（指南 §二.6）：容器缺 `type container`；物体编号断号；
`info` 与 `mis/err/extra` 相互矛盾；小物体缺失颜色。

## 四、指令语言（instr）

- 三种指令 `info` / `task` / `cons` 的格式严格按**附录B**（条件集合与顺序均须一致）。
- `cons` 指令结尾**四个括号**，其他指令**三个括号**。
- 一个物体用 `X`，两个物体第一个 `X`、第二个 `Y`，均大写且不可互换位置。
- `(:cons_notnot` 内层只能是 `(:info`。
- **同一道题中不得出现重复的 `task` 或 `cons` 指令**（规则 §2.1）。
- 一条指令中不能同时出现两个小物体；`on`/`near` 关联的两个物体不能都是小物体。
- `goto` 作用的物体可以是大物体，或不在手爪/盘子/容器中的小物体。
- `instr` 的 `info` 句描述的内容必须与环境真实状态一致。

对应检查：`check_appendixB_2026.py`、`check_syntax_2026.py`、`check_rules_2026.py`、
`check_stage2_2026.py`（`info` 一致性）。

---

## 五、自然语言（nl）

- 每句以英文句号结尾；**句子数量与顺序必须与 `instr` 中的指令一致**（逐句一一对应）。
- 单词出自自然语言词汇表，不更改词义与词性，不合并单词；句型按附录C。
- **`info`、`instr`、`nl` 三处凡涉及小物体都必须有对应的颜色描述**（规则 §2.7 三(2)）。
- 第二阶段允许在颜色词、名词中插入干扰字符（除英文句号和空格外的 ASCII 字符）；
  两个阶段均允许字母大小写混杂（非必须）。

对应检查：`check_submit_2026.py`（逐句对应 + 句型关键词 + 小物体颜色）。

## 六、分值设计

单题理论满分（指南 §五 / 规则 §2.5 二）：

```
理论满分 = 40 × 完成的目标数 + 20 × 维护的约束数 − 行动扣分 + 效率分
行动扣分 = 4 × move + 2 × 人机交互行动 + 2 × 其他物理行动 + 1 × 观察行动
效率分上限 100（规定时间 5 秒，每提前 0.1 秒加 2 分；核算理论满分时记 100）
```

- 单题理论满分须落在 **200–1000**；超过 1000 按 1000 计，负分按负分计。
- 约束分与效率分均以**至少完成一个目标**为前提。
- `info` 句为补充信息，**不计入**目标/约束数。

对应检查：`check_rules_2026.py`（上限）、`check_submit_2026.py`（用官方 validator
输出的 ASP 可行方案核算理论满分下界，`≥200` 即安全）。

## 七、提交前自查流程

```bash
# 1) 一键终检（8 项）
bash scripts/robocup-终检.sh tests/stage1 tests/stage2

# 2) 官方 validator（语法 + ASP 可解性）；判据只看"真 UNSAT"(Execution failed)
TO_MS=30000 bash scripts/run_validate.sh tests/stage1 s1
TO_MS=30000 bash scripts/run_validate.sh tests/stage2 s2

# 3) 生成提交包（按规则 §2.7 二的命名与结构）
bash scripts/robocup-打包.sh <抽签顺序> <学校> <队伍名称> <stage1|stage2>
```

判定口径：**`unvalid` 不必等于题面缺陷** —— 需区分「真 UNSAT（题面逻辑矛盾）」、
「ASP 超时（求解窗口不足）」与「格式/解析错误」三种情形；只有真 UNSAT 才是题面问题。

## 八、2026-10-16 整改记录

针对第一阶段实际被扣 1000 分（2 道题）暴露出的两类问题，本轮完成如下修正：

1. **阶段开关**：早期版本第一阶段 `mis` 误写为 `on`；已按指南修正为 `mis="off" err="off" ans="off"`，
   第二阶段为 `mis="on" err="on" ans="on"`（60 题逐一核对）。
2. **容器描述字段顺序**：早期为 `(sort)(size)(type)(closed)(at)`；已按附录A 修正为
   `(sort *)(size *)(at *)(type * container)(opened|closed *)`。
3. **`inside` 指令的条件集合**：`(:info (inside X Y))` 与 `(:cons_notnot (:info (inside X Y)))`
   的条件为 `(sort X *) (color X *) (sort Y *)`，**不含** `(type Y container)`；
   带 `type` 的只有 `putin`/`takeout` 的 `Y` 与 `open`/`close` 的 `X`（附录B）。
4. **第二阶段信息组织**：`mis` 段留空、小物体位置全部落在 `info`
   （指南 §二.3 为"可以"而非必须；§二.2 注(2) 的省略前提是字段出现在 `mis/err` 部分）。
   第二阶段难度由 `err` 的误导位置与 `ans=on` 时的交互不确定性维持。
5. **错误信息不制造死局**：`err` 的 `w` 不得把物体放进"被 `cons_notnot(closed X)` 或
   `cons_not(open X)` 保护的容器"，否则机器人照错误信息取物必然违反约束
   （生成器已内置该规则）。
6. 新增自动化检查脚本 6 个（见第四节表格），并固化"一键终检 + 提交包生成"两个脚本。
