## 一、项目定位

中国机器人大赛 · 服务机器人仿真项目。3D仿真家庭机器人，程序用9种原子行动
序列完成任务，按效率评分。两个子项目：
- **IT**（指令语言）：平台直接给 `(:ins ...)` 结构化指令
- **NT**（自然语言）：给受限英语句子，需 NLU 转结构化指令

比赛分两个阶段（第一阶段 ans=off 初始信息正确；第二阶段 mis/err/ans=on
初始信息可能错误，需 AskLoc/Sense 验证重规划）。

参赛代码：`~/Downloads/robocup-home-robot`（GitHub, SSH 推送）
本地平台：`~/Downloads/Planner-release-2025/Planner-release-ubuntu18/`

## 二、系统架构

```
include/cserver/plug.hpp   ← 客户端框架：Plug基类 + 9原子行动 + AskLoc + Sense
example/main.cpp           ← 入口，调用 Devil::Plan()
example/devil.cpp          ← 规划主逻辑（Plan + 各任务执行函数）
example/environment_manager.cpp ← 环境状态解析与更新（Env状态机）
example/instruction_parser.cpp ← :ins 结构化指令解析
example/nlu.cpp            ← NT英文 → 结构化指令（SimpleNLU）
bin/cserver                ← 平台服务器（127.0.0.1:7932）
bin/example                ← 编译产物客户端
lib/libasp.so              ← 评分库
res/iclingo                ← ASP求解器（平台验证行动合法性）
```

### 原子行动
`Move(x) PickUp(a) PutDown(a) ToPlate(a) FromPlate(a) Open(a) Close(a)
PutIn(a,b) TakeOut(a,b)`；`AskLoc(a)→"not_known"|"(on a b)"|"(inside a b)"`；
`Sense(vec)`。每行动平台返回 bool。

### 评分公式
```
基础分 = 40×完成目标 + 20×维护约束(须完成≥1目标才计) − 4×move − 2×(人机+物理) − 1×观察
效率分 = 2×⌈(规定时间−结束时间)×10⌉×完成目标数
```

### 第一阶段环境格式（实测）
`mis="on" err="off" ans="off"`。domain 以 `(hold X)` 开头，然后是 `(plate Y)`，
之后各 `(sort id type)` `(size ...)` `(at ...)` `(inside ...)` `(color ...)`
`(type ... container)` `(closed/opened ...)`。

★ **解析顺序陷阱**：`(plate Y)` 在 domain **开头**，早于 `(sort ...)`。
parse_predicate 处理 plate 时对象尚未创建，`on_plate` 不会被设上。
已修复：`parse_from_domain_string` 末尾统一补设（devil.cpp 相关，见下）。

## 五、退步题根因分析（本次重点）

### ★5.1 核心Bug：on_plate 标记不随动作更新（★最隐蔽）

**现象**：`update_after_pickup` 和 `update_after_putdown` 都没有清除/设置
`on_plate` 标记（environment_manager.cpp 488-506 行）。

**后果链**：
1. 物体在盘上 → `on_plate=true`（domain开头补设）
2. 机器人执行 `FromPlate` 拿起它 → `execute_pickup` 里 `update_after_pickup`
   只清 valid_inside/valid_at，**on_plate 仍是 true**
3. 物体已不在盘上，但标记仍 true
4. 后续再次执行该物体的 pickup（如 putin 流程中"放下→开门→重新拿起"，
   见 execute_putin_task）→ devil.cpp:989 `if (obj->on_plate)` 误判 → 走 FromPlate
   → 物体不在盘上 → **FromPlate 返回 false**，任务失败

**70.xml 实锤**（得分 80，最低）：
```
环境: (plate 18)  (hold 10)  任务含 "Put a can in the closet"
动作序列: ... [FromPlate 18|true] [Move 7] [PutDown 18] [Open 7] [FromPlate 18|false]
```
第二次 `FromPlate 18|false` 就是 on_plate 未清除导致的。can 18 已被拿起又
放下，再执行时走错分支。

**影响范围**：所有含盘上物体 + 二次拿起流程的题（putin/puton 需中途放下的）。
54/61/64/70/74/80/93/94/95 都含 FromPlate。

**修复方向**：
- `update_after_pickup`：`on_plate = false`（拿起后不在盘上）
- `update_after_putdown`：根据放下位置判断（若放回盘子则 true，否则 false）
  —— 但当前 putdown 只在 Move 后调用，应设 false
- `update_after_putin/puton/takeout` 同理需同步

### ★5.2 解析顺序：plate 在 domain 开头（已修复，但需验证边界）

`(plate Y)` 早于 `(sort ...)`。原代码 `if (objects.find(id)!=end)` 依赖对象
已存在，plate 解析时对象未创建 → on_plate 从未设置。已在
`parse_from_domain_string` 末尾统一补设（遍历 plate_objects）。当前基线已含
此修复。

### P2：AskLoc 返回 inside 格式被丢弃
`update_from_askloc`（environment_manager.cpp 417-484）只认 `at(id,loc)`
格式，遇到 `inside(a,b)`（AskLoc 文档明确支持）直接返回"格式错误"。
但第一阶段 ans=off 时 AskLoc 对盘上物返回 `at`，对容器内物才返回 inside。
第一阶段大部分场景 at 够用，**但需确认是否有题因 inside 解析缺失而低分**。
（★历史教训：加 inside 解析曾实测 -270 负收益并回退。本项需谨慎，可能不适用。）

### P3：TakeOut 失败无兜底（77.xml 得136分）
`execute_takeout` 失败后仅打印调试信息，不尝试 AskLoc 或重规划。
第一阶段 ans=off 时容器状态已知，此场景应较少；但 77.xml 出现 TakeOut|false。

### P4：冗余动作（74.xml 得94分）
"PickUp后紧跟PutDown同物" —— 效率分被冗余 move/action 拖累。

### P5：close/putin 同容器排序（59/67 得104分）
"状态任务排序"已修过一次（7620），但 59/67 仍得104，需确认是否同容器
