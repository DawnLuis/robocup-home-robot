## 一、我在做的项目

我参加的是中国机器人大赛 · 服务机器人仿真项目。在这个仿真里，一个家庭
机器人要在 3D 场景里靠 9 种原子行动完成任务，平台按效率和正确性打分。
整个赛项分两个子项目：
- **IT**（指令语言）：平台直接给我 `(:ins ...)` 结构化指令，我不需要理解
  自然语言，照着执行就行。
- **NT**（自然语言）：平台只给一段英文描述，我得先把英文翻译成结构化指令
  （NLU），再去执行。这段最难，也最花时间。

比赛分两个阶段。第一阶段初始信息是准确的，正常规划就行；第二阶段初始信息
可能故意给错（mis/err/ans 全 on），需要我自己用 AskLoc/Sense 去验证、推翻
错误信息重新规划——这是第二阶段最大的坑。

`example/IT/` 和 `example/NT/` 是两套参赛代码）

## 二、搭建环境的坑

**比赛机器是 Ubuntu，不是我的 Arch**。这给我踩了个大坑：src/ 平台代码在
Ubuntu 上原样就能编译，但我在本地 Arch 上得先做 Boost 1.92 移植（6处）才能
编译。参赛代码 example/ 是跨平台的，不用管。另外 iclingo 是个 32 位预编译
二进制，在 Ubuntu 上要装 libc6-i386 等 32 位支持库。

在 Arch 上，Boost 1.92 移掉了我用的老接口，得这么改：
- `platform.hpp`：`boost::asio::io_service` → `io_context`
- `platform.cpp`：`asio::io_service&` → `io_context&`；`new asio::io_service`
  → `io_context`；`asio::deadline_timer` → `asio::steady_timer`
  （`std::chrono::seconds(1)`）
- `plug.cpp`：`io_service` → `io_context`；`address_v4::from_string` →
  `make_address`

构建和跑测试：
```bash
sudo pacman -S boost   # 依赖 Boost 1.48+
cd .../build && cmake .. && make -j$(nproc)
cd ../bin && mkdir -p log && cp -p ../res/iclingo ../res/*.lp .
chmod +x iclingo       # ★必须！32位静态二进制，cp后常丢+x
./cserver -td ../tests/example -eval ../lib/libasp -log log -mode it -test all
# 另开终端: ./example    跑完看 log/Dawnluis.log
```
自动化：`bin/run_tests.sh all|it|nt`、`bin/run_single.sh <it|nt>`。端口被占
用就 `pkill -f cserver`。

**★坑12（最隐蔽）**：系统时钟跳变时，make 报"时钟错误"却仍显示 "Built
target"，其实根本没重编。我判定改没改进去的标准是：`bin/example` 时间戳有
没有刷新到当前时刻、`.o` 有没有重编译。**变体**：`.o` 路径是
`build/example/CMakeFiles/example.dir/*.o`，不是 `build/CMakeFiles/...`，
rm 错路径会静默用旧 binary。还有，C++注释根本不进 binary，所以不能用
strings 验证注释串，只能看时间戳或实际跑分。

## 三、代码架构

```
include/cserver/plug.hpp   ← 客户端框架：Plug基类 + 9原子行动 + AskLoc + Sense
example/main.cpp           ← 入口，调用 Devil::Plan()
example/devil.cpp          ← 规划主逻辑（Plan + 各任务执行函数）
example/environment_manager.cpp ← 环境状态解析与更新（Env状态机）
example/instruction_parser.cpp ← :ins 结构化指令解析
example/nlu.cpp            ← NT英文 → 结构化指令（SimpleNLU）
bin/cserver                ← 平台服务器（127.0.0.1:7932）
bin/example                ← 编译产物客户端
lib/libasp.so              ← 评分库
res/iclingo                ← ASP求解器（平台验证行动合法性）
```

### 原子行动
`Move(x) PickUp(a) PutDown(a) ToPlate(a) FromPlate(a) Open(a) Close(a)
PutIn(a,b) TakeOut(a,b)`；`AskLoc(a)→"not_known"|"(on a b)"|"(inside a b)"`；
`Sense(vec)`。每行动平台返回 bool，条件不满足就是 false。IT 模式 ts 字段
= `(:ins ...)` 结构化；NT 模式=受限英语句子。

### 评分公式（我背下来的）
```
基础分 = 40×完成目标 + 20×维护约束(须完成≥1目标才计约束分) − 4×move − 2×(人机+物理) − 1×观察
效率分 = 2×⌈(规定时间−结束时间)×10⌉×完成目标数
单题满分 200-1000，两阶段总分排名
```

### 评分规则的关键细节（读 evaluate.lp + 平台源码挖出来的）
- **evaluate.lp 第41行**：`:- occurs(pickup(A),1), h(plate(A),0)` —— 物体在
  盘上（plate(A)为真）时，我执行 `pickup(A)` 是**非法的**，平台直接返回
  false。
- `fromplate(A)`（57-63行）：想从盘上取物，**唯一的合法动作**是它，要求物体
  在盘上而且我空手。
- `toplate(A)`（49-55行）：要求我手持物体，把手里东西放上盘。
- 容器门关着（closed）时不能 putin/takeout；open/close 都要求空手且在同一
  位置。
- 环境 `(hold 14)(plate 15)` 开头，hold=0 表示空手（代码里映射成 -1）。

## 四、阶段格式（我自己扒平台文件确认的）

- **第一阶段 Stage1 = `mis="on" err="off" ans="off"`**，不是指南字面写的
  "全 off"。平台 problems/{IT,NT}/stage1 全是这样。mis 段放小物体的初始
  at/inside 位置（正常信息），err 空，ans 正常。
- **第二阶段 Stage2 = `mis="on" err="on" ans="on"`**（mis 错位 + err 错误值
  + ans 可能答错）。

第一阶段环境 domain 以 `(hold X)` 开头，然后是 `(plate Y)`，之后才是各
`(sort id type)` `(size ...)` `(at ...)` `(inside ...)` `(color ...)`
`(type ... container)` `(closed/opened ...)`。

★ **解析顺序陷阱**：`(plate Y)` 在 domain **开头**，早于 `(sort ...)`。
我的 parse_predicate 处理 plate 时对象还没建出来，`on_plate` 根本设不上。
已修复：在 `parse_from_domain_string` 末尾统一补设（遍历 plate_objects）。

★ **err 的 r/w 语义真相（读 platform.cpp 源码实锤）**：
- `getEnv4Grader()`（评分）= info + missing_info + **correct_info(r)** +
  extra_info → **评分用的是 r=正确值**
- `getEnv4Plug()`（传给机器人）= info + ... + **erroneous_info(w)** →
  err="on" 时机器人拿到的是 **w=错误值（专门误导我）**
- **这跟出题指南字面（r=错误/w=正确）正好相反！** 以平台源码为准：r=正确/
  评分，w=错误/误导机器人。我出题时 err 段必须写成 **r=正确位置, w=错误
  位置**，否则评分和我看到的就颠倒了，30 题全废。

## 七、NLU 修复（08-31，我最花心思的一段）

NT 7158→7298，NLU 输出 vs expected instr 匹配率 0/48→24/48：
- **Bug A**：task 分支 open/close 谓词 opened/closed→open/close
- **Bug B**：info 分支改成精确句式（is closed/opened/in/on/near/there is/
  not opened/not closed），不裸靠 "door of"；info 分支放到 task 前 → 
  "close door of X" 是 task(close)，"is closed" 不会被误判成 task
- **Bug C**：cons_not 内层用 is_task_origin 标记（不是猜句子）
- **Bug D+F**：plate 关键字 → (plate X) 谓词，覆盖 cons_notnot/info
- **Bug E**：give 特殊处理，从 objects 里去掉 human
- **Bug G**："is not opened"→closed，"is not closed"→opened（这是信息取反，
  不是 cons_not）
- **教训★**：分支顺序必须是 cons_notnot→info→task→negated。我把 task 放
  info 前，会让 "is closed" 被误判成 task(close)，分数降；改回 info 在前才
  恢复。

**第二轮修复（匹配率 23→24）**：①info 分支 relation_map 遍历前先查
"is opened"/"is closed"（否则 "washmachine" 里的 "in" 子串会被误判成 inside）
②task 分支入口加 `!contains(opened)&&!contains(closed)`，防 "must not be
opened" 这种状态句被当 task(open) ③negated 分支加 plate 条件识别 "must not
be on plate"→cons_not(plate)。

**第三轮修复（为规范题，30/30 匹配）**：①去掉容器 type 生成的 `!is_negated`
限制 → cons_not/cons_notnot 内层容器任务也生成 type ②inside 谓词的 Y 若为
容器也补 type ③**word_contains 替代 contains 做 relation_map 遍历（★关键）**：
"closet" 含 "close" 子串，contains 会把 "in the closet" 误判成 closed；三处
relation_map 遍历全改 word_contains（整词匹配，对 "next to" 等多词 key 也
有效）。

**匹配率瓶颈真相**：剩下不匹配的多半是 example 题自己 NL/instr 矛盾（NL 说

## 十、cons_notnot 解析 bug + 主动满足（我踩过又回退）

- **解析 bug 根因**：`(:cons_notnot` 以 `(:cons_not` 开头，被当成单重否定；
  而且它是 **13字符**（不是12），substr(12) 会留下一个 't'；parse_rule 里
  `(:info` 先匹配，导致 is_double_neg 分支永不触发。修法：①parse_instructions
  先判断 `(:cons_notnot` 并 substr(13) ②parse_rule 把 is_double_neg 判断提到
  `(:info`/`(:task` 前。
- **主动满足实测负收益★**：我新增 execute_fact_task 把 FactRequired 转成
  puton/putin 执行，NT 7620→7302 下降。原因：cons_notnot 说 "X must be on

## 十一、on_plate 生命周期 bug（★本次核心，已修复）

### 根因
我的 `update_after_pickup`（environment_manager.cpp:488）和
`update_after_putdown` 都**没清 `on_plate`** 标记。

### 后果链
1. 物体在盘上 → `on_plate=true`（domain 开头补设）
2. 机器人 `FromPlate` 拿起它 → `update_after_pickup` 只清 valid_inside/
   valid_at，**on_plate 仍是 true**
3. 物体已经不在盘上了，但标记还是 true
4. 后面再 pickup 这个物体（putin 流程里"放下→开门→重新拿起"，见
   execute_putin_task）→ devil.cpp:989 `if (obj->on_plate)` 误判 → 走
   FromPlate → 物体不在盘上 → **FromPlate 返回 false，任务失败**

### 70.xml 实锤（修复前得分80，全场最低）
```
环境: (plate 18) (hold 10)  任务含 "Put a can in the closet"
动作序列: ... [FromPlate 18|true] [Move 7] [PutDown 18] [Open 7] [FromPlate 18|false]
```
第二次 `FromPlate 18|false` 就是 on_plate 没清导致的。can 18 被拿起又放下，
再执行时走了错分支。

### 修复内容
`environment_manager.cpp` 5 个 update_after_* 同步维护 `on_plate`：
- `update_after_pickup`：+`on_plate=false`（★核心）
- `update_after_putin` / `update_after_puton` / `update_after_takeout`：同样清
- `update_after_putdown`：注释说明不重设（放下位置非盘时已由 pickup 清除）

### A/B 对照结果（权威，逐题对账）
| 指标 | 值 |
|------|-----|
| 基线 NT | 7578 |
| 修复后 NT | 7608（第1次）/ 7606（第2次复现）|
| 净收益 | **+30~32** |
| 关键题 70.xml | 80 → **116（+36）** ★确定性修复 |
| 其余波动 | 93/85/96 各-2，复现后漂移（85+2, 84/99-2），纯运行波动 |
| IT 模式 | 7870（48/48 全得分）|

### 修复后 70.xml 验证
- 修复前：`[Open 7][FromPlate 18|false]` ← 盘上物二次拿起走错分支失败
- 修复后：`[Open 7][PickUp 18|true][PutIn 18 7|true]` ← on_plate 已清，正确
  PickUp，任务成功完成

### 影响范围

74/80/93/94/95 都含 FromPlate。

## 十二、find_object 两遍扫描（09-02，+118 历史突破）

- **评分规则实锤**：evaluate.lp 41行——物体在盘上时 `pickup(A)` 非法，只有

- **解析顺序 bug（已修）**：`plate` 谓词在 domain 开头，早于 `sort`，原代码
  依赖对象已存在 → on_plate 从未设置。修复：parse_from_domain_string 末尾

- **两遍扫描逻辑（★关键改动 +118）**：①第一遍只找"可自由拿起"物体（不在盘
  上/容器内/未被持有）→ 避免误选盘上物（破坏 plate 约束）或容器内物；②第二
  遍 fallback：该类型物体都在盘上/容器中才选。修好了 68(+68), 76/75(+44),
  74(+32), 91(+56), 96(+48), 80(+28), 99(+30), 54/61(+40) 等。
- **副作用（退步题，待深挖）**：引入了 59/67(-56), 60(-52), 70(-52), 55/57

  putdown/close/goto 类任务（plate=15），理论上不受 find_object 影响（它们
  用 find_object_by_type 或根本不找物体）——疑为物体选择副作用或平台非确定
  性，要重跑基线逐题确认。★其中 70 的退步已确认就是 on_plate 生命周期 bug

### 规范题出题方法论（08-31 手写模板驱动）
- **手写30个完整自洽模板 > 自动随机生成**：随机生成环境+任务容易产生无法
  执行/不一致的题。我的每个模板同时产出 env + instr + nl，而且三者引用
  **同一份物体分配**（obj 含 sort/color/ctype），保证一致。

  说 red book 但 instr 写 blue）。正确做法：用占位符/Obj 引用，变体只改物体
  分配，instr/nl 从分配动态生成。

  一致。

## 十六、诊断工具（我自己用的）

1. **逐题得分打表**：
   `awk '/<.*\.xml>/{t=$1}/# Score:/{print t, $NF}' log/Dawnluis.log | sort`
2. **失败动作统计**：
   `awk '/<.*\.xml>/{t=$1}/# Results:/{f=1} f&&/\[[A-Za-z]+[^\[]*\|false\]/{print t": "$0} f&&/# End/{f=0}' log/Dawnluis.log`
3. **AskLoc 返回格式分布**：
   `grep -oE "AskLoc [0-9]+\|(at\([^)]*\)|inside\([^)]*\)|not_known)" log/Dawnluis.log | sort | uniq -c`
4. **plate 诊断脚本**：`scripts/plate_diag.py`（按题列 plate 物体+任务类型，
   秒定位"某类型只有1个且在盘上→任务误选破坏 plate 约束"的低分题）

**我定位低分题的标准流程**：①跑一遍拿每题得分排最低分 ②拉低分题完整动作
日志（awk 按 xml 切块取 # Results）③统计失败模式——PickUp|false 计数 +
AskLoc 返回格式分布 ④对照原始 xml 的 info/mis 段核对环境真实状态 vs 代码
认为的状态 ⑤回到源码看对应路径是不是有解析或判定 bug。

**典型失败模式→根因速查**：多次 PickUp|false + 多次 AskLoc 返回 inside =
update_from_askloc inside 格式 bug；Open|false + 容器 closed = 容器状态没
更新或没开门前置；冗余 Move|true 到已到位位置 = 位置更新缺失。
